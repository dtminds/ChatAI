# 消息查询相对时间

固定时间和相对时间统一沿用订单查询的自然日容差：配置和发布时，实际回溯或跨度达到 91 天才拦截，允许 91 天减 1 毫秒；界面仍提示不能早于 90 天前、跨度不能超过 90 天。选择确认时拒绝非法固定范围并就地提示；发布校验再次检查。动态时间规则不变。

产品明确约定：90 天回溯、偏移和跨度限制仅用于配置与发布，不是运行时门禁。已发布的固定时间不会因为时间推移而失效；Runtime 不调用包含这些产品限制的 Execution 完整性校验。运行时只保留结构、日期合法性、身份及实际起止顺序检查。不能把缺少运行时 90 天检查当作漏洞补回。

在现有固定时间、动态时间外新增相对时间，动态时间仍为默认模式。交互沿用消息查询自身的单选切换和开始、结束两行结构，使用现有数字输入、单位下拉和共享 TimePicker。

相对时间以当前节点 enteredAt 为稳定基准，重试不改用服务器当前时间。每个端点先减去配置的天、小时或分钟，再按 UTC+8 设置所选时分，与订单查询一致。开始端为分钟起点，结束端包含 59.999 秒，与消息查询固定时间一致。默认开始为过去 30 天 00:00，结束为过去 0 天 23:59。

配置时偏移为非负整数，各单位最多等价于 90 天。配置与发布时实际回溯和跨度均必须小于 91 天，因此允许「90 天前 00:00 至今天 23:59」。前端以当前时刻校验，运行时以节点 enteredAt 解析相对时间但不再校验回溯或跨度上限。Draft 允许编辑中的倒置范围；发布拦截可确定的倒置范围，实际倒置仍在查询前终止。动态时间规则不变。不增加数据迁移。

Contract、Web 归一化/配置/摘要/发布校验及 Runtime 解析支持新增模式。Compiler 保留相对时间配置，不要求动态变量；Live Revision 仅从 dynamic 模式提取变量，相对时间无需引用前置节点。Backend 沿用共享草稿校验，Worker 沿用已解析的 rangeStart/rangeEnd，无接口或 SQL 变更，仍单次查询最多 50 条，无自动翻页。
